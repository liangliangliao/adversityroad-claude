## 三、方向环的缺口（补片段即自动生效，无需改代码）

| 档 | 已有方向 | 缺的方向 |
|---|---|---|
| 0 走 | -90° 0° 90° 180° | -135° -45° 45° 135° |
| 1 慢跑 | -90° 0° 45° 90° 135° 180° | -135° -45° |
| 2 跑 | -90° 0° 90° 180° | -135° -45° 45° 135° |
| 3 冲刺 | 0° | -135° -90° -45° 45° 90° 135° 180° |
| 蹲伏 | -90° 90° 180° | -135° -45° 0° 45° 135° |

缺的方向不会留空——`BlendDirectional` 会在相邻两条之间插值、或退到 `NearestCoveringTier` 借上下档的片段。
所以缺口表现为"这个方向的步子不太对"，而不是"这个方向不动"。

两点必须说清楚，免得照着这张表下判断时判错：

1. **斜向那两条的角度是运行时实测的，不是表里写的。** `Jog Forward/Backward Diagonal` 在 `Add(..., measured: true)` 下
   会用 `clip.SampleAnimation` 量髋部位移反推真实角度——Mixamo 的斜向片段是左前还是右前各家素材不一样。
   所以 45°/135° 这两行**实际可能落在 −45°/−135°**。屏幕上第四行 HUD 打的是真正在播的片段名，以它为准。
2. **左右不对称是真的。** 慢跑档只有一侧有专用斜向片段，另一侧靠 0° 与 ±90° 插值补出来——
   于是同样是斜着跑，一边有专用步法、一边是混出来的，读作"往一边跑更自然"。
   补法是去 Mixamo 把那条斜向片段勾上 Mirror 再下一份，丢进 `Anims/` 即可，代码不用动。

## 四、参数含义

- **倍速下限**：真正的播放速度由招式帧数据反推，这里只是下限（见 PlayIndex）。
- **起手裁切 / 收招裁切**：片段的 [start, end] 归一化区间。Mixamo 原始片段前 12~22% 是摆架势、尾部 20~32% 是走回站姿，都要裁掉。
- **可保持**：播到 end 处停住不回落（格挡、蓄力、倒地、死亡）。
- **变体池**：同一姿态挂多条，每次轮换（受击、斩击、掉头）。
