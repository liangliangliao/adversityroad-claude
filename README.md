# 逆境之路 AdversityRoad

Unity 第三人称动作冒险 RPG：把现实中的困境转译为可战斗、可识别、可反击、可成长的敌人与场景。

> 看见弱点 → 面对困境 → 主动战斗 → 失败复盘 → 强化意志 → 再次挑战 → 逆袭成长

- 引擎：Unity 6000.5（URP，安卓/PC 双端）
- 打包：GitHub Actions + game-ci/unity-builder（推送到 `main` 或 `claude/**` 分支自动构建安卓 APK，Library 已缓存）

### 方案对齐 · 四大新关卡（本次迭代）

按最终商业化方案把 Demo 四关一 Boss 补齐成型：

- **小题大做审判庭（方案关卡一）**：倾斜的法官席 + 两侧旁观者席阴影；6 枚**浮动标签**
  （"太敏感/小题大做/你也有问题"……）悬浮在通道上空，用兵器击碎回补自尊、降低反刍；
  **证据桌**走近即"看清事实"——此后标签一击即碎（事实先于评价）；**破碎镜子**回补自尊。
  Boss【自我否定法槌】三阶段：**标签弹幕 → 审判冲击波（大红圈预警）→ 自我否定重锤（追身落锤）**；
  二阶段起触发**围攻审判**（旁观席召唤旁观嘲笑者），重锤落地后**法槌裂缝显现**=短暂破绽窗口
- **噪声放大（方案关卡二 Boss）**：回到噪声街区，街心广场上的【刺激放大器】——
  街道新增**噪声区**（广告牌下/公交站旁：站入专注缓慢流失，定心姿态减免、不读心盾免疫，影响很轻防晕）；
  周期性**噪声放大**（全场专注冲击，定心格挡/不读心盾可整个化解）；制造**幻影假目标**
  （攻击幻影=把力气花在猜测上：掉专注、涨反刍）——「不读心盾」使幻影显形消散、
  「注意力回收」全场清除后猛攻真身
- **拖延沼泽（方案关卡三）**：主入口在**噪声街区尽头东南侧**（第九章开启的一瞬门就解锁，
  全链路不再有"提前出现的锁死门"）；浅泥轻减速/深泥重减速+行动力流失、**干地平台**落脚、
  **手机光点区**（站入即流失专注与行动力）、**目标石板**（站上恢复行动力）、床铺藤蔓与漂浮计划纸。
  Boss【明天之王】**泥壳护体**（伤害大减打不动）——点燃场边**三座五分钟火种台**（走近即点燃）
  泥壳崩裂进入长破绽；战斗中召唤明日泥怪、往玩家脚下浇灌临时深泥
- **旧事回声馆（方案 Demo Boss·旧我回声）**：博物馆展柜长廊——靠近展柜触发**旧事回声**（反刍上升），
  站定完成**归档**（看见事实→命名感受→提取边界→转化行动），归档 3 座开启终局大门；
  失败展廊有旧话复读者/过去判官/反刍虫群把守。终局 Boss【旧我】四阶段：
  **旧话复读 → 身份冻结（「五分钟火种」解冻）→ 失败召回（召唤前章旧敌幻影）→ 整合选择**——
  残血后旧我停手且无法再被攻击（血线保护），走进**整合圆环**完成「旧我整合式」：
  **旧我化为影子护卫**随行（永久保存，靠近时反刍消退加速）。
  核心台词：「你曾经保护过我，但现在我要继续往前。」

### 战斗系统（借鉴黑神话悟空框架）

- **双系连段（招式全部绑定 Mixamo 动作库真实动作）**：
  拳=巨剑连斩「巨剑横斩→巨剑撩斩→突刺→巨剑旋风斩」，腿=腿法连段「正踢→侧踹→旋身空翻踢→飞踢」，
  两系可自由混接；动画从发力相位起播+提速播放，命中后即开取消窗口——连点无缝衔接不糊招
- **组合招式（连点拳/腿按序自动成招）**：拳拳拳=三连斩·大回旋、腿腿腿=三连腿·裂空飞踢、
  拳拳腿=双斩·空翻旋踢、腿腿拳=双腿·贯心突刺；2 势绝招：拳拳腿腿=龙卷·旋风绝斩、
  腿腿拳拳=踏空·裂地跳劈、拳腿拳腿=剑影·惊鸿飞踢（终结动作均取动作库大招）
- **摇杆磁吸锁敌**：攻击范围内有敌人即自动咬住目标出招（摇杆用于多敌间选目标、或明确指空处脱离），
  磁吸突进差多远冲多远，连点每一击都实打实命中
- **意势系统**（棍势式资源，0-3 点）：命中轻击/完美闪避/蓄力积攒，HUD 圆点显示，满势脚下亮起光环
- **蓄力重击**：按住「重」沉腰举械蓄力（耗体力、积意势），松开释放**蓄力·巨剑跳劈**；
  **势≥2 触发旋风终结**（消耗全部意势大幅增伤）；连段中轻点「重」派生**切手·撩斩**快速反击；
  指令技（轻点重+方向）：前=疾影突刺、后=旋身空翻踢、左右=旋风斩；跳中按重=空袭·裂地跳劈
- **完美闪避**：在敌人攻击命中瞬间翻滚 → 短暂时缓 + 意势+1 + 下一击必暴击（敌人攻击带 0.28s 前摇可读招）
- **空中攻击**：跳+拳=空袭跳劈、跳+腿=飞踢、跳+重=空袭·裂地跳劈；
  **蹲伏攻击**：蹲+腿=扫堂腿（贴地环扫、高削韧）、蹲+拳=低位突刺（下段直线戳击）
- **空中连段**（一次滞空两段，跳跃不再只是位移手段）：第二段剑向=**空中回旋绝斩**
  （环身横扫 + 滞空续航，浮空斩打得完），拳向=**空中连环踢**（压地收招，干净落回）；
  跳+重同样占用滞空额度，落地清零——空中不能无限刷伤害
- **招式规格表（`MoveSpec.cs`：轨迹 / 范围 / 判定点线面 / 伤害，敌我同构）**：
  每一招都有明确规格——轨迹分七类（**点**短促直击 / **线**直线穿透 / **横弧**横扫一片 /
  **纵弧**纵向挑击 / **环**环身 360° / **面**罩住前方 / **空**凌空罩落点），
  各带横宽 × 纵高 × 纵深（米）、判定中心、伤害系数、削韧系数、击退值。
  战斗判定框与「招式表」面板**由同一份规格派生**，不会出现"说明书写 2 米、实际打 1.5 米"
  （「招式表」面板四页：基础规则 / 自由融合 / 玩家数据 / 敌人数据，后两页由规格表实时生成）；
  敌人另有 `EnemyMoveTable`——**同一套结构、各自调值**（玩家大招要付蓄力与意势的代价，敌人不付），
  敌人判定框现按招式轨迹取形：突刺细长（侧移可躲）、回旋斩环身（只能拉开或跳）、
  重砸罩一片（须提前翻滚穿到侧后方），读招之后终于"知道该往哪躲"
- **自由融合连招（`ComboFusion.cs`：放开限制，一切动作都是连招元素）**：
  元素表 = 拳P · 剑K · 重H · **跃J** · **闪D** · **术S**（技能/绝招）· **架G**（招架成功）——
  跳跃、闪避、技能不再是自成一体的孤岛，而是可被前后动作接住的一环。
  - **融合增伤按「用到几种不同元素」阶梯上升**：2 种 ×1.15 / 3 种 ×1.35 / 4 种 ×1.60 /
    5 种 ×1.90 / 6 种以上 ×2.25。单一元素连打（只会拳拳拳拳）没有加成——
    奖励的不是"背下正确按键顺序"，而是**临场把各种手段串起来的能力**；
    招名由实际打出的元素动态生成（拳→跃→剑→术 打出「拳·跃·剑·术 — 四元融合」）
  - **跨元素融招**（在融合链上匹配，与拳剑序列配方并行）：跃→剑=踏空斩·凌云一式、
    闪→剑=闪身突刺·后发制人、术→剑=术后追斩·势不可挡、架→剑=架后反斩、重→剑=重斩接锋，
    跃→重→剑=踏空三叠·裂地崩斩（1 势）、架→拳→剑=架打连环·后发先至（1 势），
    跃→术→剑=踏云术斩·天倾一击（2 势）、闪→术→拳=影遁术拳·无相连环（2 势）
  - **连段收招不清空融合链**（链在 2.2 秒内有效，超时才断）——跳跃/闪避/技能正是用来
    在两段连招之间搭桥的，一收招就清零等于把"跨系统串招"从根上取消掉；
    融合倍率同时作用于普攻、空中段、技能连段的每一段
  - 屏幕左侧连段条改显示**当前融合链与倍率**（「拳·跃·剑 ×1.35」），
    "再换一种手段"的收益当场可见
- **双角色 + 武器库 + 面具库（角色/武器/面具三者资产分离，内置 glTFast 支持 glb/gltf）**：
  「角色」面板先选角色（角色·贰=`PlayerModel2`，glb/gltf/fbx 均可、动作沿用角色壹动作库、
  缺失自动回退；**异源骨架自动对齐**——glb 角色骨名无 mixamorig 前缀/层级不同时自动改名
  与链路对齐，默认动作库直接可用），再从武器库（`Characters/Weapons/`，glb/fbx/gltf/zip）
  选武器——默认持剑（模型无自带兵器时程序化长剑兜底），重选即替换：**握持对齐+手指握拳**
  （复刻角色壹自带巨剑的世界空间握姿、柄端入掌心、五指绕柄轴卷曲攥住剑柄）；
  再从面具库（`Characters/Masks/`，fbx/glb/gltf/zip）选面具戴脸——自动定尺贴脸、随头骨转动，
  支持多面具切换；三者选择均本地持久化。动作库补位：放入 Blocking/Stand To Roll/Stunned/
  Great Sword Casting/Leg Sweep 等专用片段即自动替换现有替代动作（见 MIXAMO_SETUP.md）
- 格挡（边界盾）/ 精准格挡（定心格挡化解心理攻击）；锁定与互动全自动化（无需按键）
- **战斗可读性（对标商业动作游戏的产品化打磨）**：
  - **近镜角色淡出**：镜头贴近任何角色（近身缠斗/贴墙）时该角色整体淡为半透明，
    根治"整屏被模型糊脸/镜头穿模"；镜头碰撞回缩下限抬高，不再缩进身体
  - **角色保持原色**：玩家与敌人均不做整体染色，保留模型原本材质与肤色；
    敌我识别交给头顶状态条、前摇红圈与恶意台词
  - **屏幕固定连击计数器**（格斗游戏惯例）：连击数固定在屏幕右侧弹缩显示、越高越红、断连淡出，
    不再跟着命中点满场乱飞；招式名浮字节流（同名招 0.9s 内不重复弹），战斗信息不刷屏
  - **夜战保底亮度**：夜晚/暗场景环境光与主光下限上调，看清双方拳脚与前摇优先于氛围
- **部位受击反应**：按命中点定位身体部位（头/躯干/腰腹/左右腿），被打部位向打击方向甩动回弹
  （打头甩头、扫腿屈膝），接触点弹出部位标签；冲量可叠加——连打两下头就有两次可见甩头；
  重击倒地为「当场栽倒」：受击位移只在身体后仰头几帧内完成，全程零漂移滑行
- **战斗反馈**：伤害数字、受击闪红、碎块飞溅、顿帧、震屏、程序化动作姿态（前倾挥击/翻滚/倒地/僵直/施法/死亡倒伏消散）；
  **程序化音效**（零外部资产，运行时 PCM 合成）——挥击风声/命中闷响/重击/格挡/定心弹反/前摇警示/受击/死亡各有其声；
  刀光改为细窄半透明加色的一道光（非大色块），绝招/组合技为「能量光爆」（强闪光+放射光条+上升火星+细冲击环）而非平铺色板
- **招式分工**：拳=快攻（出手快、低击退、高频衔接），腿=击退（大幅推开、打断突进），重击=破防（高削韧击破霸体），
  防御=减伤（体力格挡免伤 80%），闪避=反击（完美闪避时缓+返势+必暴击），意志技/定心格挡=反制心理攻击
- **重击倒地**：高伤害攻击将玩家击倒，倒地演出 + 起身无敌帧
- **敌人头顶状态条**：名字+等级、血条、韧性条、实时情绪（窥伺/紧逼/狰狞/讥讽/慌乱）

### 心理攻击（语言+情绪层面）

- 敌人实时**恶意台词**：头顶气泡 + 底部字幕，按弱点轴与所在场景组合（追击中持续低语，心理攻击时高声喊话）
- 受击**暗角脉冲**：物理伤害红色、心理伤害紫色
- **AI 提示词配置**（游戏内「AI台词」面板）：全局提示词 + 各场景提示词均有**默认模板**，可随时修改
- **云端 LLM 台词生成**：支持 **OpenRouter / DeepSeek / EdenAI**（OpenAI 兼容 Chat 接口），
  游戏内配置 API Key 与模型；**延迟方案**——进入区域即后台预取一批台词入池（区域×弱点轴），
  敌人喊话即取即用零等待，池空/断网/未配置时无缝回退本地模板

### 防晕设计（镜头/帧率/后处理/移动）

- **帧率**：安卓默认 30 帧已解锁——目标帧率取屏幕刷新率（60–120），并启用 Frame Pacing（Swappy）稳定帧间隔
- **镜头**：跟随点为平滑 CameraTarget（水平/纵向均临界阻尼软跟随，极短时间几乎无滞后又滤掉逐帧
  移动微抖动，消除晃屏与橡皮筋游动感），转角临界阻尼平滑无过冲，FOV 固定 62° 永不变化，
  碰撞回缩快伸出慢不弹跳，震屏改为极小纵向脉冲（无随机抖动），专注低不再摇镜头（改由暗角表达）
- **三模式运镜（角色转向快 / 位置中速跟随 / 镜头旋转慢）**：
  - **探索镜头**（无敌）：位置用中速 `SmoothDamp` 跟住玩家、角度基本固定；**玩家一转向，
    镜头即刻开始平稳缓慢地转到其背后（面朝方向）**——用大平滑时间的临界阻尼弹簧，转身即跟、
    小抖动只带来极轻微慢移不晃屏；树木/建筑遮挡自动透明
  - **战斗镜头**（锁定敌人）：取景点偏向「玩家↔敌人中点」让**两人同框居中**、压低俯仰、
    适度拉近看清拳脚与前摇。**与探索共用同一套稳定设施**（此前战斗分支是只有 4° 死区的
    裸伺服，探索独有的滤波/迟滞/意图识别/墙壁减速/手动让位一条都不走，
    而近身缠斗恰恰方位角变化最剧烈——2m 处敌人以 2.5m/s 横移就是 71°/s）：
    - **渐进软区**（驱动量＝偏差×(|偏差|/软区)²）：小偏差增益≈0 不追抖动，
      但始终保有微弱回正力。走过两次弯路——先是二值迟滞开关（关断时硬置零角速度＝
      无限 jerk，8 秒内通断 19 次、峰值角加速度 1509°/s²，而峰值角速度只有 38°/s，
      读作"抽动发晕"）；改成硬死区后又出现死区伺服的经典缺陷：**稳态残差恰好等于
      死区大小**，镜头永久停在偏离目标 13~20° 处不再修正，读作"转动很松"，
      且按幅度筛选会把真实运动一并杀掉（0.25Hz 绕行跟随只剩 0.057，镜头基本不跟了）
    - **抗抖靠按频率筛选的低通**（`AimLowPass` 3.2），不靠加大死区——
      低通能压掉 1Hz 以上的缠斗抖动而几乎不影响 0.25Hz 的真实绕行
    - **角加速度限幅 1100°/s²，只限提速不限减速**（阻止镜头停下来只会制造拖尾）；
      只约束镜头自身的运动，玩家手动转镜不受限（自发运动不引起晕动）
  - **持续绕行限速（修复"摇杆推到底角色一直转圈"）**：
    摇杆是镜头相对的（`moveDir = 镜头偏航 + 摇杆角`），而镜头又要绕到角色背后，
    这构成一个代数环——解 `H = C + θ` 且 `C = H`，**只有 θ=0（正前）存在不动点**；
    摇杆持续推向左/右/后时方程无解，角色必然沿弧线行进，**弧的角速度＝镜头绕行速率**。

    这三条性质数学上最多同时满足两条：

    | | (a) 摇杆↔画面一致 | (b) 镜头绕到背后 | (c) 角色不画弧 |
    | --- | --- | --- | --- |
    | 主流第三人称动作游戏 | ✓ | ✓ | ✗（走缓弧） |
    | 本作曾试过的锁存参考系 | ✗（手指按左、画面向前） | ✓ | ✓ |
    | **现方案** | **✓** | **✓** | ✗（缓弧） |

    先前试过锁存移动参考系来断环，环确实断了，但镜头绕到背后后摇杆与画面就对不上——
    实测下来这个代价不可接受，已撤回。缺陷从来不是"会画弧"，而是**弧太紧**：
    本作曾以 207~322°/s 绕行，半径仅 0.9~1.4m，读作原地转圈。
    现由 `SustainedOrbitCap` 把持续绕行压到 30°/s，实测弧线半径
    **正前=直线 / 30°=5.6m / 45°=10.1m / 90°=10.2m / 180°=10.5m**，全部落入大作区间。
    限速只在**推着非正前方向**时生效（`OrbitGateAngle` 12° 起算、30° 过渡）：
    正前小幅修正不限速，摇杆回正或松开后环即消失，镜头恢复全速追平
  - **离轴奔跑的视野靠取景而非转速（引导留白 lead room）**：
    同一条恒等式还有第二个推论——镜头要在角色行进方向背后需 `H-C=0`，
    故**摇杆持续推在离轴 θ 时，镜头在几何上不可能转到背后**。
    实测持续推左 90°，把绕行上限由 30°/s 提到 340°/s，偏离角只从 **87.9° 缩到 75.2°**，
    而角色自转从 29°/s 暴涨到 **207°/s**——提速换不来视野，只换来转圈。
    所以横向/后向奔跑的"看不见前方"只能靠取景解决：焦点朝移动方向前移，
    把角色让到画面后侧、前方空间纳入画面。留白量**随离轴角增大**
    （正前奔跑视锥纵深本就足够，横向/后向最需要），上限 2.2m（角色偏离画面中心 43%，
    仍属三分位构图；2.6m/51% 就贴边了），并叠加离轴拉远 12%。
    留白量本身走 0.5s 平滑——若直接跟随摇杆瞬变，焦点会在 0.09s 内平移 1.75m
    （≈19m/s 的镜头平移），那是比原盲区更糟的晕动源
  - **转向开阔**：转向拉远由 +6% 提到 **+15%**（`_yawErr` 驱动，转完即回）。
    用**拉远吊杆**而不是**放大 FOV**——变焦会显著加剧晕动，纯位移只是把画面推开。
    角色占屏仅在转向瞬间由 40%→35%。
    三项叠加后横跑的**可见前方 5.5m→8.1m、看前时间 1.06s→1.55s（1.5 倍）**
  - **一键镜头回正（双击右半屏 / 桌面 `V`）**：同一条恒等式的最后一个推论——
    "镜头对着角色正前方"要求 `C = H`，与 `H = C + θ` 联立得 **θ = 0**。
    即只要摇杆推在非正前方向，镜头在几何上就不可能对着角色正前方，
    **与转速、与聚焦在哪里都无关**。大作对此的通行解法不是让镜头去追一个无解的目标，
    而是给玩家一个显式动作。0.35 秒 SmoothStep 到位（90° 峰值 386°/s，仍在舒适区），
    比常规自动收敛（0.67s）快 1.9 倍；**回正期间冻结移动参考系**——
    否则快速绕行会把角色一起拖转（0.35s 可拖出 90°），回正反而把人转晕。
    锁定敌人时回正目标改取敌我方位（仍是"看向要打的人"）
  - **回正现在也是自动运镜的一部分**（见下方专节）：交战中未锁定时，
    **取景窗**负责"看得见"（敌人在窗内镜头完全不动，出窗才推回窗沿；窗宽由相机
    FOV 与宽高比精确解出，手机上约 ±30°），
    **自动回正**负责"看得正"（松杆时做一次 0.4~0.8s 的动作把敌人摆回画面中央）。
    玩家主动的一键回正照常保留
  - **各角度的可见前方（实测，取景三项叠加后）**：

    | 摇杆偏角 | 改前 | 改后 |
    | --- | --- | --- |
    | 0°（正前） | 不受限 | 不受限 |
    | 30° | 11.2m / 2.16s | 15.1m / 2.91s |
    | 45° | 8.1m / 1.55s | 11.3m / 2.18s |
    | 90° | 5.8m / 1.12s | 8.7m / 1.67s |
    | 180° | 5.5m / 1.06s | 8.2m / 1.59s |

  - **转向的完整时间线（实测）**：正前奔跑中推左 90°、按住 h 秒后松杆——
    松杆后镜头对准新行进方向恒定只需 **0.68~0.70s**（此时无代数环，全速收敛），
    视野打开（偏差<20°）只需 0.67s。这一段已接近舒适上限：
    峰值角加速度 904°/s²，再压缩到 0.52s 需 1050°/s²，收益 0.15s 而超出舒适区，不值。

    对照旧的不限速版本：对准略快（0.87s vs 1.03s），但**转向会转过头**——
    按住 0.8s 时角色从意图的 -90° 冲到 -227°（多转 137°），并伴随 207°/s 的自转。
    即"提速"不只带来转圈，还让转向不准

    三版实测对照：

    | 版本 | 0.25Hz 真实跟随 | 1Hz 抖动传递 | 稳态残差 | 峰值角加速度 |
    | --- | --- | --- | --- | --- |
    | 原始裸伺服 | 0.731 | 0.326 | 4.0° | 4800°/s² |
    | 硬死区 13° 版 | 0.057 | 0.000 | 13.0° | 290°/s² |
    | **现版（软区 8°）** | **0.659** | **0.097** | **1.0°** | **234°/s²** |

    - 偏差→速度连续映射、墙壁减速、手动转镜让位
    - 实测传递率：1 / 1.5 / 2.5 Hz 的方位抖动由 **0.32 / 0.22 / 0.13 降到 0**，
      而 0.25 Hz 的真实绕行仍保持 **0.63** 跟随——该动时动、该稳时稳
  - **3/4 侧位机位**：战斗时镜头不站在玩家正后方的延长线上（那是最平庸的机位——
    玩家挡住敌人、双方只剩背影与正面两个平面）。偏开一个肩位（22°）后是对峙的经典构图：
    玩家侧背、敌人侧脸，**拳脚的运动轨迹横穿画面**而不是朝镜头戳过来（纵向运动在屏幕上
    没有位移感）。偏哪一侧由两侧可用空间决定，需领先 0.6m 才换边，切换走 1.4 秒慢插值
  - **景别词汇表**（`CameraDirector`：行进中景 / 对峙同框 / 群战拉远 / 狭窄收紧 / 决胜特写）：
    参数级插值＝推轨过去，不是切镜。狭窄判定改为只看**吊杆真正要退去的方向**——
    旧实现取四周六向最短值，只要靠近任何一面墙就推近镜头，哪怕镜头正对开阔地
  - **特写的克制**（"知道何时特写"的另一半是知道何时不特写）：节流 2.6 秒 +
    **群战抑制**（身边 ≥3 个敌人时强度砍半、时长压短——看清包围态势比欣赏这一击重要）+
    强度分级（超必杀满推、处决 0.75、高阶融招 0.65、击杀/完美闪避轻推）。
    此前每个敌人死亡都触发 1.1 秒满推特写，群战连杀会把镜头长期焊在贴脸位
  - **视线高度随景别**：特写抬高到面部、群战压低把包围圈纳入画面；
    此前恒定不变，于是"推近了却仍对着胸口"——推近只是变大而没有变成特写
  - **掉头不再有盲区**：全速前进后立刻反向奔跑，实测盲区（新方向进入画面）
    **开阔 1.58s→0.75s、贴墙 3.21s→0.80s**。四处叠加的延迟逐一拆掉：
    - **`backingIntent` 判据修正（主因，0.6 秒冻结）**：此前用"朝镜头行进了多久"
      区分「转身看正脸」与「掉头往回跑」——可掉头时偏差同样是 180°，被同一条规则
      冻住 0.6 秒。两者输入相同、意图相反，可靠的区分是**速度**：前者原地转身或碎步、
      后者全速持续移动。现按 `moveSpeed > 0.55×runSpeed` 判定，低速看正脸的行为不变
    - **稳定确认时长随偏差缩短**（0.15s→0.02s）：小幅修正需要确认防摇杆抖动，
      180° 掉头本身就是无歧义的意图，再等 0.15 秒纯粹是加盲区
    - **墙壁减速下限 0.25→0.6 且掉头幅度越大越不减速**：旧值把贴墙掉头从 1.15s
      拖到 2.60s，换来的只是吊杆好看一点——而吊杆顶墙本就有碰撞回缩兜底，盲区更要命
    - **二级平滑随偏差缩短**（0.11s→0.05s）：串联的固定平滑在掉头时又多花 0.33 秒
    - **掉头甩镜（whip pan）**：全速反向且偏差 >120° 时转速上限提到 5×（425°/s），
      实测峰值 359°/s，仍在人眼舒适上限内；普通转向不走这条路
- **取景开阔度（实测重调）**：原 vFOV 56° + 吊杆 4.76m 下，角色占屏高 **45%**、
  水平视野仅 **86.8°**——主流第三人称动作游戏是占屏 28~36%、水平 95~105°。
  "人物有分量"被做过头成了"人物填满画面"，这正是「压抑、不开阔」的直接成因。
  更反向的是「对峙」景别还把 FOV **再收窄 1°**，战斗时比探索更闷。
  调参走了两步：65°/吊杆 5.25m 实测「偏晕且角色变小」，回到 **62°/吊杆 4.76m**——
  只保留 FOV 加宽、撤回吊杆加长。两者都会缩小角色，但只有 FOV 能真正扩大周边视野，
  吊杆加长只是等比缩小画面里的一切。角色占屏与视野开阔是直接对立的两个量，
  40% 是这条曲线上的折中点，不是"两者都要"的解。各景别实测：

  | 景别 | 水平 FOV | 角色占屏 | 原始 |
  | --- | --- | --- | --- |
  | 行进·中景 | 93.8° | 40.2% | 86.8° / 45.4% |
  | 对峙·同框 | 94.9° | 38.6% | 85.6° / 45.5% |
  | 群战·拉远 | 98.2° | 33.2% | 91.5° / 33.7% |
  | 狭窄·收紧 | 100.3° | 43.7% | 92.6° / 50.0% |
  | 决胜·特写 | 91.5° | 53.6% | 80.6° / 64.9% |

  贴墙极限回缩下限 1.6→1.9m：1.6m 处角色占屏 **135%**（整个画面被身体填满），
  是贴墙时"突然极度压抑"的来源
  - **第一人称**：镜头在眼睛高度、脸前方，俯仰自由——低头看见自己的手/脚/剑，抬头看见天空，
    挥剑/踢腿低头即见肢体与兵器在空中运动；只隐藏头部，身体其余可见
  - 底层：转角/位置均临界阻尼平滑无过冲
- **遮挡自动透明**：树木（含无碰撞体的树冠）挡在镜头与玩家之间时自动淡出为半透明，移开即淡回
- **移动**：加减速平滑（速度无突变），摇杆全向 360° 模拟量走跑（极小死区仅滤静止噪声）；
  人形步态叠加脊柱反向扭转/躯干侧倾/骨盆侧摆/落步点头等次要动作，消除机械感
- **后处理**：运行时强制关闭运动模糊/色差/镜头畸变/噪点，暗角强度限幅

### 言语攻防 · 反刍 · 战后复盘（本次迭代）

把方案里最核心的循环——「语言打语言、事实打赖账、边界打索取、不读心打刺激、复盘代替反刍」——落成可玩机制：

- **言语攻防（快速选择式）**：敌人发动心理攻击（凝视/低语）时，屏幕下方弹出**三选一回应**面板
  （一句「最优回击」+ 两句「无效回应」，随机打乱，5 秒倒计时，战斗不暂停用非缩放时间计时）。
  - **选对**：敌人**语塞进入破绽**（削韧，可击破触发大破绽）、对应弱点属性回补、反刍下降，**且不吃这次心理伤害**
  - **选错/沉默**：照常吃心理伤害，并**额外累积反刍**（互骂/退缩/过度辩护只是把自己拖进反刍）
  - 回应库按弱点轴给出最优句（如噪声轴「我听见了，但我不跟随」、边界轴「帮助有边界，这次你自己承担」、
    求职轴「没有回应不代表没有价值，我再来一次」），全部抽象化、服务战斗机制，绝不输出现实操控话术
  - 冷却/恢复模式/已在进行时自动回退为原来的即时落伤害
- **内部言语攻击（脑内回声·本次迭代）**：方案的「内心敌人字幕攻击」落地——
  言语攻防不只来自外部敌人，也来自玩家**自己的脑内回声**。反刍累积到 ≥55%
  （或场上有 `Internal` 类内心敌人逼近且反刍 ≥35%）时，第一人称的负面念头浮出
  （「我是不是根本不行？」「万一又失败了呢？」「明天再开始也一样」），用同一套
  三选一言语攻防回应：**答对**→脑内回声散去、反刍下降、对应属性回补；
  **忽略/答错**→照常吃心理伤害并额外累积反刍（越回避越回放）。反刍越高、内心
  敌人在场，触发越频繁；与外部言语攻防、休养生息答题互斥（同一时刻只弹一个模态）
- **反刍值（方向相反的消耗条）**：越满越糟。被心理攻击命中即累积，选错回应额外增加；
  战斗外缓慢消退避免软锁；上升时紫色暗角脉冲提示
- **行动力 ActionPower（本次迭代·替代"决断"）**：拖延轴攻击/深泥/手机光点消耗它，
  **过低时移速明显下降**（拖延的具象体感）；五分钟火种/火种台/目标石板恢复
- **关系消耗值 RelationshipDrain（本次迭代·第二条反向消耗条）**：被索取/责任转嫁类攻击、

| **决胜·推近特写** | 大招 / 处决演出 | 推近 ×0.78、压低、**长焦 −5°**——看清这一击的分量 |

- **优先级**：决胜 > 狭窄 > 群战 > 对峙 > 行进。**狭窄优先于群战**——地方都不够站，
  拉远只会把镜头顶进墙里，这是学徒最容易犯的错
- **过渡即一切**：所有景别参数（距离/高度/俯仰/焦段/同框比例/阻尼）都做**指数插值**，
  镜头是**推轨**过去的而不是切过去的；且切换速率因情境而异——
  进特写果断（4.5/s，要有戏剧性）、出特写从容（2.2/s，不惊扰）、进狭窄要快（3.5/s，
  否则已经顶墙）、其余缓慢（1.6/s，几乎察觉不到）
- **场地感知**：向镜头四周 6 向投射取最短可用距离，识别走廊/贴墙——
  镜头开始"知道自己站在什么地方"
- 敌情与场地扫描 0.3s 节流一次，不做每帧全场遍历

### 与官方/开源参考的参数核对（本次迭代）

对照 [Unity 官方 ThirdPersonController](https://github.com/nrsharip/unity-third-person/blob/main/Assets/StarterAssets/ThirdPersonController/Scripts/ThirdPersonController.cs)
与 [UE SpringArm 官方示例](https://dev.epicgames.com/documentation/unreal-engine/using-spring-arm-components?application_version=4.27)
逐项归一化核对，结论是**本项目数值本就在标准区间内**：

| 项目 | 本项目 | 官方参考 | 判定 |
| --- | --- | --- | --- |
| 跑速 | 5.2 m/s | Unity 5.335 m/s | 几乎一致 |
| 走速 | 2.6 m/s | Unity 2.0 m/s | 同量级 |
| 重力 | −20 | Unity −15 | 略重（动作向） |
| 角色转向时间常数 | 0.071s | Unity RotationSmoothTime 0.12s | 更跟手（战斗向） |
| 土狼时间 | 0.12s | Unity FallTimeout 0.15s | 同量级 |
| 镜头吊杆长度 | 4.76 m | UE SpringArm 3–4 m | 更长＝视野更开阔 |
| 镜头位置跟随 | 0.09s | UE CameraLagSpeed 3.0 → 0.33s | 远比 UE 跟手 |
| 视野 | 垂直 56°（@16:9 ≈ 水平 87°） | UE 第三人称模板 水平 90° | 不算窄 |

**这一核对本身就是结论**：此前所有卡顿/盲区/不连贯问题，根因都是**结构性缺陷**
（体力静默中断连段、互斥分支漏掉中幅转向、消费式输入互抢、镜头意图模型错误），
而不是数值不对——所以"照抄别家参数"解决不了，必须逐个定位逻辑。

**唯一有实据可改进的一处已采纳**：Unity 官方用**指数逼近**做加减速
（其注释原文：*curved result rather than a linear one giving a more organic speed change*），
本项目原为线性匀加速（`MoveTowards`）。已改为 `1−e^(−k·dt)` 指数逼近（帧率无关）：
起步 k=20（0.05s 到 63%、0.15s 到 95%）、刹车 k=26——起步瞬间给足冲量更跟手，
末段自然收敛不突兀。

### 镜头意图识别（本次迭代 · 「面壁转身看正脸却被甩向墙面」）

实测反馈：**面前是墙、用摇杆转身想看清角色的脸，镜头却立刻绕开去看墙面。**
这不是参数问题——是镜头的**意图模型**错了：它假设「玩家永远想看角色的正前方」，
于是把一切转身都读作"要换行进方向"。补上两层意图识别：

**① 区分「转身看一眼」与「真要往那个方向去」**

角色朝镜头走来（偏差≈180°）时，此前一律绕到背后。改为按**是否持续行进**判定：

| 玩家行为 | 镜头 |
| --- | --- |
| 短暂转身看正脸 / 贴墙后退调整站位 | **岿然不动**——看得到正脸，视野不塌 |
| 持续朝镜头方向跑 **>0.9s** | 缓缓绕过去——角色不会跑出画面 |
| 战斗中转身打背后的敌人 | **豁免**，仍快速追击（看见敌人优先） |

**② 不把镜头甩进墙里**

大幅回正前先**探测目标方位的空间**（与主碰撞同一套过滤规则）：越憋屈转得越慢
（最低降到 **25%**）。面壁转身时"绕到角色背后"恰好是墙的方向，硬绕过去只会让镜头
顶在墙上被迫贴脸、视野瞬间塌掉——现在会把镜头留在看得见的地方。

**③ 手动取景保护 0.3s → 1.2s**：玩家刚手动摆好角度，镜头 0.3 秒后就自己转回去，
读作"和我抢镜头"；1.2s 让手动取景有足够停留时间。

### 镜头同步跟随统一化（转向尺度 → 镜头幅度）

> ⚠️ 本节的两条判据已被下方「战斗跟随信号」一节修正：
> 「正在推杆也计入主动意图」与「威胁方向挂在朝向上」在**战斗中**是抖动的直接来源。
> 保留此节记录当时的取舍。

目标：**转向/移动幅度越大，镜头同步调整越快；任何情形下都不留盲区。**
核查发现此前的实现还有两个覆盖缺口：

- **战斗中 12°–55° 的中幅转向完全没有跟随**——战斗与探索是互斥的 `if / else if`
  两条分支，`InCombat` 为真时只走战斗分支（需 >55° 才启动），中等幅度转向被两边都漏掉，
  这是战斗中长期存在的**部分盲区**
- **技能/出招期间推杆转向不跟随**——出招时角色被"定步"锁住只转不移动，
  `moveSpeed≈0` 被判定为静止，回正条件不成立

改为**一条统一的渐进跟随曲线**（无分档断层）：

| 情形 | 行为 |
| --- | --- |
| 中小幅转向（>10°）+ 有移动**或推杆** | 温和跟随，偏差越大越快 |
| 大幅换向（战斗 >55° / 探索 >45°） | 迟滞开关锁定追击，直到 <12° 才松开 |
| 站立不动且未推杆 | 完全不动（无漂移） |
| 手动转镜期间 | 一律让位给玩家 |

- 角速度按偏差**连续映射**：平滑时间 0.5s→0.15s、转速上限 **70→340°/s**——
  小幅修正慢而稳（防抖），大角度掉头迅速跟上（防盲区），两者不再互相牺牲
- **「正在推杆」也计入主动意图**：覆盖出招/技能中的转向，角色转到哪镜头跟到哪
- **视野开阔化**：疾跑与大幅转向各给一点点拉远（合计 ≤ +12%，变焦极慢）——
  转身掉头的瞬间正是最需要看清周围的时刻，给"要去的方向"留出可见余量

### 战斗跟随信号：朝向 → 行进方向（本次迭代 · 「摇杆走位出招时镜头频繁抖动」）

实测反馈：**摇杆一边走位一边和敌人出招时，方向稍有变动镜头就频繁抖动、非常敏感**；
而黑神话悟空这类游戏没有这个现象——它们的方向操作与镜头操作是**分开**的。

前几轮已经把稳定设施做得相当完整（低通、渐进软区、角加速度限幅、绕行限速、一键回正），
但这一条症状它们一条都治不了，因为**问题不在滤波器，在喂给滤波器的信号**。

**根因：未锁定的战斗，镜头追的是「角色朝向」。**

锁定是**手动**的（`LockOnSystem.AutoAcquire` 默认关，对齐魂系惯例），
所以绝大多数近身互殴 `lockTarget == null`，走的是**探索分支**——而探索分支追
`_headingAvg`（角色朝向）。战斗中角色朝向恰恰是全场最跳的量：

| 来源 | 朝向变化 | 是否触发 220°/s 的稳定计时清零 |
| --- | --- | --- |
| 出招磁吸 `ApplyAttackFacing` | 每一击**瞬间**拧向敌人 | 单帧瞬转，之后立刻恢复累计 |
| 轻击连段推杆转向 | 150°/s | **否**（低于阈值，一路畅通） |
| 技能/绝招 `SteerDuringAction` | 85~110°/s | **否** |
| 翻滚起手 | 直接硬赋值 | 单帧 |

再加上 `threatAhead = ThreatNear(_headingAvg, 70°)` 在交战中**几乎恒真**
（只要你面朝正在打的那个敌人就成立），它把启动门槛压到 `holdNeed 0.06s`、
`bigAngle 35°`，迟滞开关全程锁死。于是摇杆的每一次细碎方向调整都经由
朝向被忠实地送进镜头——这就是"很敏感、频繁抖动"。

**改法：交战中改追「真实行进方向」。**

行进方向（低通后的水平速度方向）对上述四种朝向跳变**天然免疫**——
站着挥拳时它压根不存在。而探索时朝向 ≡ 行进方向，既有的全部调参与实测结论不受影响。

**再进一步：追错了东西——战斗中该框住的是【敌人】。**

换成行进方向后抖动大幅收敛，但**残余是几何上必然的**：移动是镜头相对的 ⇒
`行进方向 = 镜头偏航 + 摇杆角` ⇒ **偏差 err ≡ 摇杆离轴角 θ**。
追一个恒等于 θ 的目标**永远不会收敛**——只要摇杆偏着推，镜头就一直以绕行限速
（30°/s）缓缓爬。宏观上不是"抖"，但读作**"镜头永远不安定、很敏感"**。

于是先试了"干脆全关"——**结果把镜头的首要职责也扔了：打着打着敌人跑出画面、
不知道在哪**。这一步是过度修正，随即撤回。

复盘下来，两次弯路的共同点是**追的都是 `C+θ`**：无论"角色朝向"还是"行进方向"，
它们都是镜头偏航的函数，构成代数环，既抖又不收敛。而战斗中该框住的从来是**敌人**——
**敌人方位不是镜头偏航的函数，没有代数环，追它天然收敛。**

**追法：取景窗（camera window），而不是伺服到画面中央。**

| 敌人屏幕角 | 镜头 |
| --- | --- |
| 落在窗内（水平半视野的 58%，手机上 ±30°） | **完全不动** |
| 出窗 | 只把它**推回窗沿**，到位即停——不追到中央 |

- **为什么不追到中央**：那意味着镜头必须跟着敌人的每一步走，正是要根治的
  "永远在轻微动"。推回窗沿则"一到位就停"，静止是常态，动一定是因为真的要出画

**这里第一版把窗宽写死成 34°，结果整套逻辑是个空转**——照 FOV 半宽 47° 估的，
却漏掉了**镜头在玩家身后 4.6m 造成的向心压缩**：玩家身边的东西在画面上天然靠中间。

| 敌人距玩家 | 屏幕水平角**上限** |
| --- | --- |
| 1.5m | 19.0° |
| 2.0m | 25.8° |
| 2.5m | 32.9° |
| 3.0m | 40.7° |

近身缠斗（1.5~2.5m）**永远达不到 34°**，那段代码每帧都判"在窗内"而什么也不做。
现在窗宽由 `Camera.fieldOfView + aspect` 精确解出水平半视野再取 58%（16:9 → ±27°、
19.5:9 → ±30°），换 FOV／换屏幕比例都自动跟着走。

其余实现要点：

- **屏幕角用镜头【真实的 forward】量**（`Vector3.SignedAngle`），不从 `_curYaw` 反推：
  肩后构图的横向偏移让实际视线偏离 `_curYaw` 约 5.6°，反推会让取景窗左右不对称
  （24° vs 36°）；`SignedAngle` 还天然表示"敌人跑到镜头背后"（|角|>90°）
- **低通滤【敌人位置】而不是屏幕角**：屏幕角里同时含有镜头自身的转动，滤它等于把
  本回路的反馈也延迟 τ≈0.31s，与伺服时间常数同量级，必然过冲振荡
- 目标切换有迟滞：当前敌人还活着且在 16m 内就继续咬住，绝不因为"另一个刚好近了
  0.2m"就换人——换目标＝一次大幅摆镜
- **撤离豁免**：持续朝背离敌人的方向全速跑时框敌让位给探索跟随——
  否则镜头会扭回去盯着你正在逃离的敌人，你就变成对着屏幕底部往里跑

**在这之上，一键回正正式接进自动运镜（原一键回正保留）。**

### 什么时候回正、什么时候绝不回正

判据只有一条，战斗与探索**共用同一条**：

> **你接下来要面对的东西，现在看得见吗？**
> 战斗看正在打的**敌人**；探索看角色**前方 6m 的「视察点」**。都用同一个取景窗量。
> 看得见 → 镜头一动不动。看不见 → 需要回正。

用"视察点在不在窗内"而不是"朝向转了多少度"，是因为前者自动把**镜头在身后 4.6m
造成的向心压缩**算进去了。代入几何解出的实际阈值：

| 角色转向 | 视察点屏幕角 | 判定 |
| --- | --- | --- |
| 15° | 8.5° | 窗内 → **不动镜** |
| 30° | 17.0° | 窗内 → **不动镜** |
| 45° | 25.6° | 窗内 → **不动镜** |
| 55° | 31.4° | 出窗 → 需要回正 |
| 90° | 52.5° | 出窗 → 需要回正 |
| 180°（从前转朝后） | 180° | 出窗 → 需要回正 |

也就是说：**±50° 以内的转向、走位、闪避、出招转向一律不动镜**——那些方向你本来
就看得见，动了就是白抖；**超过约 55° 才回正**——那时你确实什么都看不到。
阈值是从几何解出来的，不是拍的。

**「想回正」与「能回正」是分开的两件事**：

- **想**：视察点／敌人出窗持续 0.2s（滤掉一闪而过）
- **能**：**摇杆松开**（≥0.07s），或摇杆已推回接近画面正前（离轴 <35°）

"能"这一条是**几何硬要求**，不是保守：移动是镜头相对的 ⇒ `行进方向 = 镜头偏航 + 摇杆角 θ`。
推着离轴 θ 时，把镜头转到行进方向背后**无解**——转多快都一样，只会让角色画更紧的圈
（实测把上限提到 340°/s，偏离角只从 87.9° 缩到 75.2°，自转却涨到 207°/s）。
更糟的是回正一结束、参考系解冻的那一刻，摇杆的世界方向会整体旋转 θ 度，
玩家会被"掉头回去"。松杆时环消失，回正才既收敛又无副作用。

所以：**只"想"不"能"时**，由探索伺服以 30°/s 走缓弧、配合引导留白与转向拉远撑住视野，
**玩家松杆的那一瞬间立刻兑现**（0.07s 阈值——掉头时拇指扫过摇杆中心很快，抓得紧一点）。

完整的决策表：

### 镜头返工定稿：撤回一整轮加法，只留能算得清的那几条（本次迭代）

上一版把跟随重写成「先判情景、再配行为」的分派器（`CamIntent`：静止/巡航/盲区/
近身/取景/锁定/演出），只有落进「盲区」这一个情景才跟随。反馈是
**「没有效果，而且好像别的地方也被改坏了」**——两条都成立，原因也都能算出来：

**① 跟随再也停不下来（这是"被改坏"的那一半）。**
跟随的偏差恒等于摇杆离轴角 θ（`H = C + θ ⇒ H − C ≡ θ`），而 θ **不随镜头转动而改变**：
手指按着不动，镜头转多少度，θ 还是那么大。于是"盲区"这个判据一旦成立就再也不解除，
镜头以 75°/s **一直转下去**——按 5.2m/s 的跑速换算，角色在半径 4.0m 的圈里绕，
画面每 4.8 秒转满一圈，直到玩家松手为止。这正是"摇杆四个方向不停转动、
整个屏幕也跟着不停转"。
而被删掉的 `SustainedOrbitCap`（30°/s，半径 9.9m）本来正是压这个的——**删掉它是纯粹的倒退**。

**② 起手要等 0.5 秒（这是"没有效果"的那一半）。**
落进「盲区」要同时满足：持续位移 0.35s + 拇指角稳定 0.22s + 前视点出取景窗
（按镜头在身后 4.6m、前视点 4.68m 的几何反算，需要转过 **73°** 才够），
再加速率爬升 0.2~0.32s。跑动中随手一个 60° 转向，判据根本不成立；
够成立的大转向，也要半秒后镜头才开始动。

**结论：那一整套是错的方向，已全部撤回**，回到 `9d0e603` 的连续跟随（它是收敛的、
有绕行限速的、参数经过实测的），只在其上叠加**能单独算清收益**的几条：

| 保留 | 为什么它是对的（可验算） |
| --- | --- |
| **时钟统一 `Time.deltaTime`** | 每次命中都顿帧（`HitStop`：timeScale=0.08，0.035~0.12s）。原先镜头跑无缩放时间 ⇒ 世界冻住而镜头照常收敛，且 `moveSpeed = 位移(8%)/dt(100%)` 每拳塌一次，引导留白随之单帧跳最多 0.45m——与出招同频的一路抖动 |
| **`_combatBlend` 交战程度** | 此前稳镜只认「是否锁定」，而锁定默认手动开 ⇒ 绝大多数近身互殴一直吃"探索档"的跟手参数。改为锁定/出招中/身边有敌人在打三者取或 |
| **战斗中死区抬高 10°→30°、门槛 45°→62°、转速 ×0.55** | 转速 = 增益 × 偏差，而偏差 ≡ θ ⇒ **拇指的抖动被一比一翻译成镜头角速度**。虚拟摇杆拇指本就在 ±10~20° 内游走，抬高死区让这段噪声整个落进去。加平滑没用——平滑只改相位，不改幅频比 |
| **位置侧同档加重** | 焦点死区 0.03→0.15m、跟随时间常数 0.09→0.24s、引导留白上限 2.2→0.5m（近身走位是短促往复，留白只会把焦点前后甩 2.2m）；另加 6cm 纵向死区（`CharacterController` 贴地/台阶的高频跳动） |
| **出画兜底** | 稳定压倒一切，但"看不见敌人"不是稳定，是失职。8m 内正在打你的敌人掉出取景窗并持续 0.28s ⇒ 恢复全速把它推回**窗沿**（不是画面中央——推到中央意味着镜头得跟着敌人每一步走） |
| **取景窗按真实相机几何算** | 曾写死 34°。而镜头在身后 4.6m 时，敌人在 1.5/2.0/2.5/3.0m 处的屏幕角**上限**只有 19.0°/25.8°/32.9°/40.7° ⇒ 那条逻辑在近身时**几何上永远不触发**。改用 `atan(tan(vFOV/2)·aspect)`：62°@19.5:9 ⇒ 半宽 52.5° |
| **自动回正并入自动运镜**（一键回正保持不变） | 见下 |
| **回正时长按角加速度预算反解** | 见下 |

#### 自动回正：为什么时机是「松杆的那一刻」

`H = C + θ` 的最后一个推论：镜头对着角色正前方要求 `C = H`，联立得 **θ = 0**。
即**只要摇杆推在非正前方向，镜头在几何上就不可能对正**，与转速、与聚焦在哪都无关。
所以连续伺服永远追不平；而**松开摇杆的那一刻环就消失了**，那才是把镜头一次性摆正的
正确时机——也正好是玩家跑完一段、在换气的节拍，运镜发生在这里最不打扰。

四重闸门（少一条就会变成"每隔一两秒摆一次"）：

| 闸门 | 值 | 挡掉的是 |
| --- | --- | --- |
| 松杆时长 | > 0.12s | 搓杆过中心的瞬间 |
| 需求持续 | > 0.2s | 一帧的抖动 |
| 幅度 | > 25°（交战 > 55°） | 不值得动镜的小偏差 |
| 「移动刚结束」窗口 | 站定 < 1.2s | **玩家特意让镜头对着角色的脸站着**——那是他摆的机位，镜头一动都不该动 |
| 间隔 | > 2.2s（交战 > 5s） | 交战中松杆极频繁（出招/格挡/闪避之间都会松） |

#### 回正为什么"转得太快、让人头晕"

晕动的驱动量是角**加速度**，不是角速度；公认舒适上限约 **600°/s²**。
`SmoothStep` 走完 Δ 度用时 T ⇒ 峰值角加速度 = `6Δ/T²`。原先固定 0.35s：

| 回正幅度 | 固定 0.35s 的峰值角加速度 | 按预算反解后 |
| --- | --- | --- |
| 90° | 4408°/s² | 一键 0.62s / 自动 1.04s |
| 180° | **8816°/s²**（舒适上限的 14 倍） | 一键 0.88s / 自动 1.47s |

改为 `T = sqrt(6Δ / 预算)`：自动回正 500°/s²（镜头自己决定要动，最保守），
一键回正 1400°/s²（玩家自己按的，自发运动耐受度高，但仍只有原先的六分之一）。

#### 这一轮真正学到的

- **一个不收敛的回路，调多少参数都没用。** 前面几轮反复在"速率、平滑、门槛"上加东西，
  而 `H − C ≡ θ` 决定了误差压根不随镜头转动而减小。看清这一点之前，所有调参都是白做。
- **判据越"聪明"，越容易一条都不成立。** 三个串联条件各自都合理，连乘之后成了
  "跑动中随手转向永远不触发"。加判据必须验算它的**联合触发率**，不能只看单条是否合理。
- **删掉一条压制性的限速时，必须先问它在压什么。** `SustainedOrbitCap` 看起来只是
  "限制绕行速度"，实际是这个不收敛回路唯一的兜底。


### 视野开阔度裁决运镜快慢（本次迭代 · 「看得见就慢慢跟，看不见才赶紧转」）

反馈：跑动中转向**不必立刻决定切换或回正**——要看当前视野可见范围。
**开阔、能看见远方一定距离 ⇒ 后续平稳跟随即可；视野受限、看不清远方陷入盲区 ⇒
才需要快速调整到目标方向**。并且应当**尽量不让盲区发生**，始终保持前方视野开阔，
这样也就避免了镜头突然快速转动导致的头晕。另外只要视野开阔，
就不该这么频繁地自动回正。

这条反馈把"该不该动镜"的判据从**几何**（镜头在不在背后、转了多少度）
换成了**功能**（看不看得见要去的地方）——后者才是玩家真正在意的东西。
转向本身从来不是动镜的理由。

#### 通视距离：一条平射探测，两个方位

新增 `SightDistance(yaw)`：从取景点沿某方位平射（球扫，半径 0.35m，上限 26m），
返回多远才被挡住。与既有的 `FreeBoomDistance` 分工明确——
那条往**吊杆要退去的方向**探（会不会顶墙），这条往**要看/要去的方向**平探。
忽略触发器、动态碎屑、玩家与敌人本体（敌人挡一下反而是你正想看的东西）。
两次探测都做 4/s 低通，且改用 `SphereCastNonAlloc`（每帧两次，不能有 GC）。

#### 紧迫度 `_urgency`：三条来源取最大

| 来源 | 度量 | 挡的是 |
| --- | --- | --- |
| ① 当前画面闭塞 | 沿**画面正前**的通视距离，18m→0、6m→1 | 走廊、贴墙、拐角里看不到东西 |
| ② 要去的方向快撞上 | **剩余时间** `通视/速度`，3.0s→0、0.9s→1 | 跑向墙面/尽头 |
| ③ 要去的方向不在画面里 | 前视点屏幕偏角，0.65→0.95 倍半视野 | 开阔地**朝镜头跑**：通视很长却完全看不见路 |

第 ③ 条不能省——只看开阔度会漏掉最典型的那种盲区。
站定时（`moveSpeed < 0.6`）②③ 一律不成立：**站着不存在"前方"**，
否则"转身看正脸"会被读成"前方 180° 全是盲区"，镜头随即绕走。

`_urgency` 本身走 0.5s 临界阻尼——它调制着转速，若阶跃，转速就跟着阶跃，
又变回"猛地开始转、猛地停住"。

#### 关键：用【剩余时间】而不是【剩余距离】，盲区就不会发生

5.2 m/s 的跑速下 `TtiRelaxed = 3s` 对应 **15.6m**——
也就是墙还在十几米外，镜头就已经不紧不慢地开始转了，等你真跑到墙边早已对好。

**这才是"避免镜头突然快速转动导致头晕"的正解：不是把快的那一下调慢，
而是让它根本不需要发生。**

#### `_urgency` 接到哪几处

| 参数 | 开阔（→0） | 盲区（→1） |
| --- | --- | --- |
| 跟随死区 | **28°**（斜着跑也不动镜） | 10°（细碎修正也跟） |
| 转速系数 | ×0.45 | ×1.0 |
| 大幅换向追击门槛 | 70° | 45° |
| 稳定确认时长 | ×2.2（0.33s 才起手） | ×1.0（立刻起手） |

交战中另有一套并联（稳定第一）：死区固定 30°、转速 ×0.55——
战斗里"看得见敌人"由出画兜底负责，不靠通视距离。

#### 「停下来之后自动回正」已整条撤销

反馈：跑动/移动停止后镜头还会自动回正，有必要吗？——**没有，而且成熟大作里
一款都没有这个设计**：

| 作品 | 未锁定时的回正 |
| --- | --- |
| 魂系 / 只狼 / 艾尔登法环 / 黑神话悟空 | 只在**移动时**缓缓跟到身后；一停就停在原处。回正是**显式按键**（右摇杆按下 / 锁定键） |
| 战神 (2018 / 诸神黄昏) | 从不自动回正，越肩镜头只跟随移动方向 |
| 地平线 / 刺客信条 / 对马岛之魂 | 移动时温和跟随，停步不触发任何运镜；有独立的"居中镜头"键 |
| 塞尔达 旷野 / 王泪 | ZL / X 是玩家自己按的复位，停步不触发 |
| 鬼泣 5 | 混合机位 + R3 居中键 |

道理也站得住：**停下来恰恰是玩家想看看四周、看看自己角色的时刻**，
这时候把镜头摆走是最不合时宜的一次运镜；而且它无法预测——玩家没做任何动作
画面却动了，那正是"镜头有自己的想法"这种糟糕观感的来源。

功能上它也已经没有必要：连续跟随本来就在你【移动时】把镜头带到身后，
盲区时还会自动提速；停下之后即使构图偏一点，按开阔度原则——
只要看得见远方，那就不是问题。下一次起跑时跟随立刻接管，自己就正回来了。

**保留一键回正**（双击右半屏 / 桌面 `V`）：那是这个类型的通行解，
玩家自己按的运动不引起晕动。它的时长仍按角加速度预算反解（1400°/s²，
180° 用 0.88s、90° 用 0.62s），不再是会把人转晕的固定 0.35s。

#### 转向缓冲拉远：用空间换时间

反馈：跑动中突然转向时，拉远距离作为缓冲、增加视野看清远方很有必要。

确实——这和紧迫度是同一思路的两只手：一个把盲区**提前**化解，
一个在转向**当下**直接给出更多可见范围，于是镜头有余裕慢慢转过去，
**那记"猛转一下"就免掉了**。

- **用拉远吊杆而不是放大 FOV**：变焦显著加剧晕动，纯位移只是把画面推开，
  是这几个杠杆里唯一还有余量且无副作用的。
- **判据用转向角速度，不用镜头偏差**：偏差恒等于摇杆离轴角 θ，稳态推着不放
  也一直大，吊杆会长期停在拉远位并随拇指抖动前后泵动；角速度只在真的在转的
  那零点几秒里大。45°/s 起算、180°/s 满级，再乘速度（站着原地转身不给缓冲）。
- **不走 `_lenFactor`**：那条是 0.75s 的分镜级慢插值，一次 0.4 秒的转向在它那里
  几乎看不出来。单独走一条起快收慢的临界阻尼——起 0.45s、收 1.2s。
- 幅度 +22%：吊杆 4.6 → 5.6 m，可见前方约多出 1.7 m，角色占屏 40% → 33%，
  仍在主流第三人称的构图区间内。峰值推拉约 1.2 m/s，属舒适区。

#### 顺带修掉的两处「站着不动镜头却在转」

- `steering`（推杆算行进意图）改为**只在交战中**成立。它本是为"出招时移动被定步
  锁住、角色只转不移动"而加的；非战斗时推杆必然产生位移，`moving` 本就覆盖得到，
  而它反倒把"站着用摇杆改朝向"读成了"我要往那边去"。
  短促的改朝向撑不到 0.6 m/s 的低通均速，正好被滤掉。
- 大幅换向的追击锁存 `_combatReorient` 此前**不看是否在移动**，
  于是站着原地转 90° 就会锁存住把镜头绕过去。现要求 `active`，
  背后有威胁 / 敌人已出画时豁免。


### 连打不再卡顿（本次迭代 · 体力静默中断连段）

实测反馈「连续快速按拳/剑/重/绝招/技能仍会明显停顿；同时推着摇杆更明显」。
算一笔账就找到了元凶——**不是延迟问题，是招根本没打出来**：

| | 数值 |
| --- | --- |
| 轻击连打频率 | ≈ 5.8 段/秒 |
| 体力消耗（旧：每段 8） | **47/秒** |
| 体力回复（旧） | 15/秒 |
| 结果 | 满体力 100 点 **连打 3.2 秒即见底**，之后每次出招 `SpendStamina` 失败 → 静默 `EndCombo` → **人站在原地不动**，每 0.53 秒才憋出一招 |

- **连段永不被体力静默中断**（核心修正）：体力不足时**照常出招**，改为进入「疲惫」——
  伤害 ×0.6、不积意势，并给节流提示。大作的原则是"打得动但没力气"，
  体力只影响**强度**，不影响**能否出招**——连打的手感必须永远连续
- **体力经济重平衡**：轻击 8→**3**、回复 15→**22/秒** → 连打净值 **−4/秒，可无限连打不见底**；
  体力的真实取舍回到闪避/蓄力这些「大动作」上
- **推杆时更明显的原因**：出招瞬间移动速度被**硬性砍到 10%**、收招瞬间弹回全速，
  配合已提速的加减速（0.09s 刹停）形成**速度震荡**，读作一顿一顿的抽搐。
  改为对倍率本身做 ≈0.07s 平滑过渡、下限抬到 0.3——既保留定步分量感，
  又让「边推杆边连打」是一条连续的速度曲线
- **技能侧**：仅在「出招锁定」时才排队重试（冷却/资源不足不入缓冲，避免每帧重试刷屏）；
  冷却与资源不足提示加节流；体力/意志不足从**静默失败**改为明确反馈

### 意图匹配：输入保真度（本次迭代 · 「人机合一」的底层）

实测反馈「对移动、动作、转向的控制不够精细灵敏，希望角色与玩家意图完全匹配」。
这类"隔了一层"的体感，根源不是速度不够快，而是**玩家按下的键没有被完整兑现**。
按大作的输入保真度标准补齐三层：

**① 通用输入缓冲 `InputBuffer`（核心）**
玩家在硬直、翻滚、出招锁定等**暂时无法响应**的窗口里按下的键，此前被整帧丢弃——
真实意图是「我现在就要闪」，却被系统读成「你按早了，重按」。现在一律记录时间戳暂存，
**恢复可控的第一帧立刻兑现**；超窗作废（防陈旧输入迟到触发）：

| 动作 | 缓冲窗 | 解决的具体问题 |
| --- | --- | --- |
| 闪避 | 0.30s | 硬直中/翻滚中按闪没反应；**连续翻滚失效** |
| 跳跃 | 0.20s | 落地前一瞬按跳被吞 |
| 技能 | 0.35s | 出招锁定中按技能石沉大海 |

- **土狼时间 0.12s**：离开平台边缘后仍可起跳——意图是"我在边缘按了跳"，不是"晚了两帧活该掉下去"
- **修复消费式输入互抢**：`MobileInput.GetDown` 每帧只能被读一次，此前 `PlayerController`
  与 `PlayerCombatController`（受身）各读一遍 `Dodge`，谁先执行谁拿到——
  **倒地时按闪常常没反应正是这个原因**。现在全局唯一消费点 + 共享缓冲（已加不变量校验）
- **修复缓冲采集时机**：输入采集原在翻滚 early-return **之后**，翻滚中的按键整帧跳过；
  已移到所有 early-return 之前

**② 移动响应提速（起步不再拖沓）**

| 项目 | 调优前 | 调优后 | 大作标准 |
| --- | --- | --- | --- |
| 0 → 全速 | 0.29s | **0.12s** | 0.08–0.15s |
| 全速 → 停止 | 0.20s | **0.09s** | ~0.10s |

防晕改由**镜头侧**负责（软跟随 + 焦点死区 + 渐进回正），而不是靠拖慢角色本体——
这是主流第三人称动作游戏的正确分工：**角色跟手，镜头稳定**。

**③ 已有的保真基础**（本次核对确认到位）：虚拟摇杆 0.06 径向死区 + 死区外重映射 0–1 +
响应曲线（小幅推杆＝精细慢走）；攻击输入缓冲 0.6s；全部旋转/位移基于 `dt` 帧率无关。

### 出招转向影响（本次迭代 · 「出招 + 推杆转向」不连贯）

实测反馈「做动作/技能/绝招同时推摇杆改变方向时不连贯、不连续」。查出三处叠加成因：

- **技能/绝招/重击期间摇杆完全无响应（主因）**：`IsHardLocked` 分支直接 `return`，
  整个 1.15–1.45 秒的技能连招里推杆毫无反馈，动作结束才**突然弹到**新朝向——
  这正是"断裂感"的来源。改为大作通用的 **attack steering（出招转向影响）**：
  硬锁动作期间仍可用摇杆调整朝向，按状态给不同角速度上限——
  技能/绝招 **110°/s**、重击/蓄力 **85°/s**（最重、转向最慢）；
  **受击/倒地/心理硬直/死亡不给转向**（挨打就该失控，这是打击反馈的一部分）
- **轻击连段转向被过度阻尼**：旧值 `Slerp(rate 2.2)` 每帧只挪 3.7%，推杆几乎转不动，
  读作"一出招就僵住"。改为明确角速度上限 **150°/s**——既能顺着摇杆把连招引向新方向，
  又不会一帧甩离当前目标
- **技能每段硬吸附覆盖玩家意图**：连招每段 `FaceTarget()` 瞬时锁向自动目标。
  改为**玩家意图优先**——推杆幅度足够且方向与目标偏差 >45° 时顺着摇杆出招，
  连招跟着你走；否则才咬住自动目标
- 摇杆输入统一在帧首读取一次，供出招转向与移动共用（消除重复计算）

### 转身盲区修复（本次迭代 · 视野变窄/看不见前方）

实测反馈「改变方向/转身时视野变狭窄、处于盲区」。定位到**两个独立成因**并分别修正：

**成因一：镜头开始回正前的等待过长（主因）**
上一轮防抖调优引入的低通滤波（固定 0.2s 收敛）+ 稳定计时门槛（0.22s）叠加，
转身后镜头要等约 **0.42 秒**才开始跟——这段时间你朝新方向走却看不见前方。修正：

- **自适应低通**：朝向还在乱动时收敛慢（滤掉摇杆抖动），一旦稳定就快速收敛（5→18/s）
- **门槛收短**：探索 0.22→0.15s、战斗 0.35→0.24s（快速搓杆仍永远攒不满，抗抖不变）
- **慢速移动也回正**：阈值 1.4→0.6 m/s——蹲行、走路、出招定步此前**完全不回正**，
  在这些状态下转身等于永久盲区
- 综合：开始回正前的等待 **0.42s → 0.21s**

**成因二：渐进式回正（小角度稳、大角度快）**
固定 85°/s 的封顶让大角度掉头追得慢。改为按偏差插值——
探索 0.5s/70°/s → 0.16s/300°/s，战斗 0.28s/180°/s → 0.15s/340°/s：
180° 掉头完全归位 **1.23s → 0.90s**，而 20° 小幅修正仍保持平缓（0.83s），抗抖不受影响

**成因三：转身时吊杆扫过墙体被拉近 → 画面贴脸变窄**

- 碰撞探测球 0.25→**0.18**：擦过墙角/柱子不再误触发大幅回缩
- 回缩下限 1.35→**1.6m**：即使贴墙也保留可用景别
- **伸出恢复 0.3→0.14s**：扫过障碍后视野立刻回到正常景别，不再长时间贴脸发窄
  （回缩仍保持 0.03s 的快速响应，避免穿墙）

### 战斗提速调优（本次迭代 · 对照大作帧数据标准）

实测反馈「动作/技能/绝招攻击速度很慢」——对照主流动作游戏帧数据做了一轮系统调优：

| 项目 | 调优前 | 调优后 | 大作标准 |
| --- | --- | --- | --- |
| 轻击起手 / 取消窗 | 0.07 / 0.20s | 0.05 / 0.155s | 0.05–0.13 / 0.13–0.18s |
| 轻击全长（拳系） | 0.40s | 0.30s | 0.25–0.35s |
| 剑系末段旋风斩 | 0.60s | 0.46s | 0.4–0.5s |
| 成招终结窗口 | 0.68s | 0.50s | 0.45–0.55s |
| **技能动作锁** | **1.7–2.2s** | **1.15–1.45s** | **0.8–1.4s** |
| 超必杀「觉醒·乱舞」 | 2.2s | 1.75s | 1.5–2.0s |
| 蓄力满 / 二连间隔 | 1.2 / 0.5s | 0.85 / 0.34s | 0.7–1.0 / 0.3–0.4s |
| 指令技冷却 | 3.5s | 2.2s | 1.5–2.5s |

- **收招闪避取消（AAA 核心手感·新增）**：技能/绝招/蓄力二连演完主要打击段、进入**恢复相位**后
  可用**闪避立刻打断收招**——不必干等动作播完，攻防转换一气呵成。这是"卡手感"的最大来源，
  也是大作（DMC/战神/只狼）通用的 dodge-cancel 规则；任何状态切换自动复位，不会误放行
- **攻击动画同步提速 ~15%**（1.4–1.7× → 1.55–1.95×）：逻辑窗口收紧后动画必须跟上，
  否则挥击相位演不完就被下一段切掉——动作依然完整，只是更"脆快"
- 闪避输入改为**每帧统一读取一次**，供收招取消与常规翻滚共用，杜绝消费式输入被读两次而丢键

### 大作级近战规则（本次迭代 · 对齐主流动作游戏手感）

参考主流大型动作游戏（阿卡姆/战神/只狼/黑神话）的战斗规则，补齐四项核心手感系统：

- **攻击令牌 · 围攻礼让**（`CombatDirector`）：同一时刻只允许 **最多 2 名普通敌人**真正发起
  攻击，其余围绕走位、伺机而动——杜绝被一群敌人同时糊脸的廉价难度，群战更有节奏、可读；
  Boss 不受限（舞台主角）；令牌在一套攻击结束、被打断（硬直/破绽）、死亡、脱战时归还，
  并有超时保险回收
- **待战环走位**（`MaintainStandoff`）：没抢到攻击令牌的敌人只逼近到玩家周围一圈「待战环」
  （攻击距离 +1.8m），太近后撤、太远贴回、在环上绕圈候场——**绝不堆挤进玩家身体**，
  真正做到「一两个进攻、其余围而不攻」，围攻不再是一拥而上的混乱
- **远程只做言语弹幕，不做物理削血**：普通敌人不配置远程物理攻击（近身格斗）；所有 Boss 的
  远程弹幕（法槌标签/凝视光束/引文/追问/硬币「才这点钱」/账单「就这一次」/旧话复读）一律
  **改为纯言语·心理伤害**（去掉远程物理削血），并受凝念能量预算限制——保留「言语攻击弹幕」的
  压迫，去掉不符合大作规则的远程物理弹雨

### 言语攻击只压心神，不扣 HP（本次迭代 · 严格对齐方案「十四言语攻防系统」）

方案明确：敌人言语攻击 →「**玩家心理数值受到影响**」、错误回应「增加反刍/内疚/羞耻」——
**不涉及 HP**。据此全面核对并修正所有言语/感知类攻击，使其只作用于心理数值：

- **纯言语攻击**（台词驱动）：`DoMentalAttack`（凝视/低语 + 三选一言语攻防，本就 `isMentalOnly`）
  与 8 处话语弹幕（标签/凝视光束/引文/追问/硬币/账单/旧话）——全部只压专注/自尊/边界/意志、
  推高反刍/关系消耗，不扣 HP
- **感知/索取型攻击**（此前误扣 HP，本次修正为纯心理）：**凝视扫射**「千目审视」→ 羞耻/自尊；
  **车灯眩光**（外界刺激）→ 专注；**索取冲击**（默认索取型）→ 边界 + 关系消耗
  （举盾明确拒绝仍触发 Boss 大破绽，联动不受影响）
- **保留扣 HP 的只有「动作攻击」**：近战连招、对攻，以及**物理力学 AoE 机制**
  （审判冲击波/自我否定重锤/概念迷环/意义崩桥/责任法槌/内疚落石——预警圈可闪避的物理招式）——
  这些是「动作打动作」，与言语攻击是两条独立路径
- **危险攻击 · 红光警示**（不可格挡）：精英/Boss 有概率使出**危险一击**——头顶亮「危」、
  地面红圈更大更亮、专属警示音、前摇略长给足反应窗口；命中**不可格挡（硬挡会被破防吃满伤）
  ，只能闪避**，教玩家看红光读招而非无脑格挡；伤害/击退加成兑现威胁
- **破韧处决**：敌人被削韧击破进入破绽期时，用**重击/大招**命中触发「**处决**」——
  巨额增伤（×2.8）+ 强顿帧 + 短慢镜 + 能量爆发横幅，把「削韧破防→抓破绽猛攻」
  做成有仪式感的收益循环
- **连段伤害衰减**：连续命中第 7 击起温和递减到最低 0.75 倍（停手 1.5s 复位）——
  正常 4—5 段连招几乎不受影响，只压制长时间锁血的无限连 cheese，鼓励收放有度的连段

- 「敌人+」面板自由添加挑战：5 种类型（明日幻影/咳声刺客/自我怀疑低语/羞耻镜像/拖延影魔）× 4 档难度（见习/标准/精英/首领，数值与体型缩放）

## 操作

### PC（编辑器 / 桌面构建）

| 按键 | 功能 |
| --- | --- |
| WASD / 鼠标 | 移动 / 镜头 |
| V | 镜头回正（一次性拉到角色行进方向背后；交战中松杆时也会自动执行） |
| 鼠标左 / 右键 | 轻攻击 / 重攻击 |
| Space / Shift | 跳跃 / 闪避（流云步） |
| Ctrl（按下瞬间为精准格挡） | 格挡（边界盾）/ 定心格挡 |
| Q / R | 锁定敌人 / 内功（意志燃烧） |
| Tab / F | 循环切换战斗姿态（起步/边界/定心/事实/意志） |
| 1 / 2 / 3 | 技能：定心护体 / 能量斩·斩念气刃 / 责任归还（法院清除过度负责、打回责任球） |
| 4 / 5 / 6 | 技能：五分钟火种（解冻/恢复行动力）/ 不读心盾 / 注意力回收（清幻影） |
| E（靠近目标板按住） | 目标板蓄力，恢复心理属性 |

### 安卓真机

- 左下虚拟摇杆移动（半推=走路，全推=奔跑），右半屏拖动转镜头；**双击右半屏＝镜头回正**
- **方向与镜头是分开的两套操作**：探索时朝同一方向持续跑，镜头才缓缓绕到身后；
  **近身交战（敌人 8m 内）镜头完全不跟方向**（不敏感、不抖）——改由取景窗把正在打的
  敌人框在画面里：敌人在画面中间一大片区域内时镜头纹丝不动，只有快要出画才推回来；
  松杆时再自动回正一次把构图摆正，敌人彻底出画超过 0.5 秒则无条件摆回去。
  **其他一切情况（无敌人／敌人 8m 外／正在撤离）镜头实时同步跟方向。**
  想全程盯住某个敌人就按「锁」
- **右下六核心键 + 一修饰键（按拇指人体工学解出的布局）**：拳 / 剑 / 重 / 闪 / 挡 / 跳 + **术**
  - 三层排布：拳（最高频）在拇指自然静止点 9.1mm 处、最大；剑/重/闪 内弧 27.3mm；
    挡/术/跳 外弧 44.3mm，且**与内弧同辐射线**——拇指沿一个方向扫出去先碰内环再碰外环，
    肌肉记忆是一维的。任意两键间隙 ≥6.6mm，高于触屏可靠间隙下限
  - **术＝技能修饰键**（借鉴手柄 L1+面键把 4 键变 16 招）：点一下亮起 3 秒，
    亮起期间六个核心键临时变成六个技能——**术→拳=定 · 术→剑=气 · 术→重=还 ·
    术→跳=火 · 术→闪=盾 · 术→挡=收**；放完自动落回普通模式，再点「术」可取消。
    亮起时按钮字面自动换成实际装备的技能名并变蓝紫，「术」自身随剩余时间收亮
  - 触屏用**点选式**而非手柄的按住式：一根拇指按不住修饰键再去点另一个键；
    平板/外接手柄真按住时同样生效，且可连放多个技能
  - 重路由发生在输入中枢（`MobileInput.SkillMap`），所以一次点击**要么出拳要么放技能，
    不会两者都发**；六个技能不再各占按钮位，战斗区从 14 键降到 7 键
  - 低频操作移出战斗区：锁定 / 拔刀收刀移到屏幕右侧边缘竖排，摇杆旁「蹲」切换蹲伏
  - 技能因此也进入融合链——术→剑 打出的是「术后追斩」，一键技能成为组合的一环
- 责任转嫁法院：**劈开文件山**取事实证据、**劈断锁链**破念解束缚、走近**责任天平**判断归属解锁「还」；
  面对 Boss 抛来的**责任球**——红球举「挡」打回、绿球别挡接下，被减速时按「还」一次清掉
- 右上角：「敌人+」添加挑战、「AI台词」配置提示词与 LLM、「角色」切换外观、「日志」查看 AI 调用记录、
  「复盘」打开战后复盘四栏（归档清空反刍值）
- 敌人发动心理攻击时，屏幕下方弹出「言语攻防」三选一回应面板——选对即可回击破防、化解伤害
- 左侧属性条下方「姿态条」五枚按钮：点选切换战斗姿态（把姿态对准来袭弱点轴即可大幅减伤）

## 获取安卓 APK

1. 推送到 `main` 或 `claude/**` 分支（或在 Actions 页手动 Run workflow）。
2. 打开仓库 **Actions → Build Unity Android → 对应运行**。
3. 页面底部 **Artifacts** 下载 `Android-Build`，解压得到 APK 安装到手机。

## 设计原则

- 游戏基于真实经历抽象为敌人原型与场景气氛，**不复刻真实人物/地点/事件**。
- 心理攻击只做成游戏机制（低语/凝视/泥潭+抽象台词），**绝不输出可复制到现实的操控话术**。
- 失败不惩罚：死亡生成复盘任务，引导策略调整后再战，章节进度保留。
- 隐私数据最小化：个人材料与提示词本地保存，支持一键删除。
